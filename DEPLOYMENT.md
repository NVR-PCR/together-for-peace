# Together for Tomorrow - Deployment Guide

## Vercel Deployment Setup

### 1. Environment Variables in Vercel Dashboard

Go to your Vercel project settings and add these environment variables:

- `SUPABASE_URL` = `https://your-project.supabase.co`
- `SUPABASE_ANON` = `your-anon-key-here`

### 2. Supabase Database Setup

Run this SQL in your Supabase SQL Editor to create the required tables:

```sql
-- Contact info table
create table public.contact_info (
  email text not null default 'placeholder@tft.edu'::text,
  name text not null default ''::text,
  class_role text not null,
  constraint contact_info_pkey primary key (email),
  constraint contact_info_email_key unique (email)
);

-- Newsletter subscriptions table
create table public.newsletter (
  email text not null,
  constraint newsletter_pkey primary key (email)
);

-- Survey responses table (stores answers as option numbers)
create table public.survey_responses (
  id bigint generated by default as identity not null,
  created_at timestamp with time zone not null default now(),
  ans1 integer null,
  ans2 integer null,
  ans3 integer null,
  ans4 integer null,
  ans5 integer null,
  ans6 integer null,
  ans7 integer null,
  ans8 integer null,
  ans9 integer null,
  "ansA" integer null,
  "ansB" integer null,
  "ansC" integer null,
  "ansD" integer null,
  "ansE" integer null,
  "ansF" integer null,
  constraint survey_responses_pkey primary key (id)
);
```

### 3. Enable Row Level Security (RLS) and Add Policies

For each table, enable RLS and add an insert policy for anonymous users:

```sql
-- Contact info table policies
alter table public.contact_info enable row level security;
create policy "Allow anonymous inserts" on public.contact_info
  for insert with check (true);

-- Newsletter table policies
alter table public.newsletter enable row level security;
create policy "Allow anonymous inserts" on public.newsletter
  for insert with check (true);

-- Survey responses table policies
alter table public.survey_responses enable row level security;
create policy "Allow anonymous inserts" on public.survey_responses
  for insert with check (true);
```

### 4. Deploy to Vercel

1. Push your code to GitHub/GitLab
2. Connect your repository to Vercel
3. The build script (`inject-env.js`) will automatically run during deployment
4. It replaces the placeholders in `index.html` with your actual Supabase credentials

### How It Works

The `vercel.json` is configured with:
```json
{
  "buildCommand": "node inject-env.js",
  "outputDirectory": "."
}
```

During the build, `inject-env.js`:
1. Reads `SUPABASE_URL` and `SUPABASE_ANON` from Vercel environment variables
2. Replaces the placeholder strings in `index.html` with actual values
3. The deployed HTML has the credentials hardcoded (safe since they're public anon keys)

### Verify Deployment

After deployment:
1. Open your browser's developer console
2. Look for: `[Build] Supabase config injected` or `[Config] Supabase credentials loaded`
3. Submit a test form - you should see success messages without "(Demo mode)" text
4. Check your Supabase dashboard to confirm data is being saved

### Troubleshooting

**Forms show "Demo mode" message:**
- Check that SUPABASE_URL and SUPABASE_ANON are set in Vercel dashboard
- Redeploy after adding environment variables
- Check browser console for error messages

**Data not appearing in Supabase:**
- Verify RLS policies are enabled with insert permissions
- Check Supabase logs for any errors
- Ensure table schemas match exactly

**Build fails:**
- Ensure Node.js is available (Vercel provides it by default)
- Check that `inject-env.js` exists in the project root
