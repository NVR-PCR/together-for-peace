# Together for Tomorrow - Deployment Guide

## Overview
This is a static website deployed on Vercel with Supabase backend integration for storing:
- Contact information (student/parent interest forms)
- Newsletter subscriptions  
- Survey responses

## Environment Variables Setup

### In Vercel Dashboard:
1. Go to your project settings
2. Navigate to **Environment Variables**
3. Add these two variables:
   - `SUPABASE_URL` = `https://your-project-id.supabase.co`
   - `SUPABASE_ANON` = `your-anon-key-here` (the public/anon key, NOT the service role key)

### Getting Supabase Credentials:
1. Go to your Supabase project dashboard
2. Click **Settings** → **API**
3. Copy:
   - **Project URL** → use for `SUPABASE_URL`
   - **anon public** key → use for `SUPABASE_ANON`

## Database Schema Setup

Run these SQL commands in your Supabase SQL Editor:

```sql
-- Contact info table
create table public.contact_info (
  email text not null default 'placeholder@tft.edu'::text,
  name text not null default ''::text,
  class_role text not null,
  constraint contact_info_pkey primary key (email),
  constraint contact_info_email_key unique (email)
);

-- Newsletter subscribers table
create table public.newsletter (
  email text not null,
  constraint newsletter_pkey primary key (email)
);

-- Survey responses table (15 questions max)
create table public.survey_responses (
  id bigint generated by default as identity not null,
  created_at timestamp with time zone not null default now(),
  ans1 integer null,
  ans2 integer null,
  ans3 integer null,
  ans4 integer null,
  ans5 integer null,
  ans6 integer null,
  ans7 integer null,
  ans8 integer null,
  ans9 integer null,
  "ansA" integer null,
  "ansB" integer null,
  "ansC" integer null,
  "ansD" integer null,
  "ansE" integer null,
  "ansF" integer null,
  constraint survey_responses_pkey primary key (id)
);
```

### Enable Row Level Security (RLS):

```sql
-- Enable RLS on all tables
alter table public.contact_info enable row level security;
alter table public.newsletter enable row level security;
alter table public.survey_responses enable row level security;

-- Allow anonymous inserts (for public forms)
create policy "Allow public insert into contact_info"
  on public.contact_info for insert
  with check (true);

create policy "Allow public insert into newsletter"
  on public.newsletter for insert
  with check (true);

create policy "Allow public insert into survey_responses"
  on public.survey_responses for insert
  with check (true);
```

## Build Process

The build process automatically injects your Supabase credentials into the HTML:

1. Vercel runs `npm run vercel-build` during deployment
2. This executes `inject-env.js` which reads `SUPABASE_URL` and `SUPABASE_ANON` from environment variables
3. The script injects these values into `index.html` before the `</head>` tag
4. The injected config is available as `window.__CONFIG__` at runtime

## File Structure

```
/workspace
├── index.html          # Main HTML file (credentials injected at build)
├── supabase-ops.js     # Supabase client and database operations
├── inject-env.js       # Build script to inject env vars
├── survey.txt          # Survey questions (loaded dynamically)
├── package.json        # NPM config with build scripts
├── vercel.json         # Vercel deployment configuration
└── public/             # Images folder
    └── *.png           # Dynamic images (named by data-photo attribute)
```

## How It Works

### Credential Flow:
1. **Build Time**: `inject-env.js` reads env vars and injects them into HTML
2. **Runtime**: Browser loads HTML with embedded credentials in `window.__CONFIG__`
3. **Supabase Client**: `supabase-ops.js` reads from `window.__CONFIG__` and initializes the client
4. **Forms**: All forms use the initialized Supabase client to save data

### Form Handling:
- **Contact Form**: Saves to `contact_info` table (email, name, class_role)
- **Newsletter**: Saves to `newsletter` table (email only)
- **Survey**: Saves to `survey_responses` table (ans1-ans9, ansA-ansF as integers)

## Troubleshooting

### Forms showing "Demo mode" message:
1. Check browser console for errors
2. Verify env vars are set in Vercel dashboard
3. Redeploy after setting env vars (they're only available at build time)
4. Check that tables exist in Supabase with correct schema
5. Verify RLS policies allow anonymous inserts

### Data not appearing in Supabase:
1. Open browser DevTools → Console
2. Look for "Supabase credentials not found" or connection errors
3. Check Supabase table structure matches the schema above
4. Verify RLS policies are enabled and allow inserts

### Build failing:
1. Ensure `package.json` exists with build scripts
2. Check that `inject-env.js` is present
3. Verify Node.js is available in build environment

## Testing Locally

```bash
# Set environment variables
export SUPABASE_URL="https://your-project.supabase.co"
export SUPABASE_ANON="your-anon-key"

# Run build script
npm run build

# Serve locally (any static server)
npx serve .
```

## Security Notes

- The `SUPABASE_ANON` key is safe to expose in frontend code (it's designed for public use)
- RLS policies ensure users can only insert data, not read/modify others' data
- Never use the `service_role` key in frontend code
- All form submissions are validated on both client and database level
